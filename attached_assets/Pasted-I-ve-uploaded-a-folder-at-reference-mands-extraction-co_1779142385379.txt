RULES FOR USING THE REFERENCE COPY

1. The structure and substance of each page should match the existing site
   closely. This is a rebuild, not a rewrite. Keep the same sections,
   the same content hierarchy, the same general messaging.

2. Apply the voice/style rules from Layer 1 as you go:
   - No em dashes (use periods, commas, or restructure)
   - No "harness the power of," "unlock the potential of," "in today's
     [X] landscape," "more than just a [X]"
   - No press-release voice
   - No AI staccato ("X is not Y. It is Z.")
   - Lead with audience outcome, not credentials
   - Flowing prose over bullet stacks where the format allows

3. Some content in the reference files lost its grouping when the Divi
   shortcodes were stripped (especially on /ai/ where the capability cards
   appear as orphaned paragraphs). Use your judgment to re-group these
   into FeatureGrid or appropriate components based on context.

4. Use the components built in Layer 2. Specifically:
   - Hero for page tops (variants: WithVideo, WithImage, TextOnly)
   - NumberedSectionMark for section headers ("01 / OVERVIEW")
   - StatCallout for any numbers/metrics that appear in copy
   - FeatureGrid for capability/service lists
   - TestimonialQuote for client quotes
   - CTABanner for end-of-page CTAs
   - TwoColumn for alternating image-text sections
   - StickyServiceNav on long pages (especially practice areas + service lines)
   - LogoCloud where the source mentions trusted clients

5. For media, reference paths under /public/media/. If the source copy
   references a specific image (e.g., MS-Brand-Photoshoot-20-1.png), use
   /public/media/brand/MS-Brand-Photoshoot-20-1.png. If an image is
   missing from /public/media/, leave a clearly marked placeholder
   comment so I can swap it in later: {/* TODO: image - description */}

6. Section rhythm: vary section backgrounds between paper (white), cream,
   and the occasional dark section per Layer 1. Roughly 60% paper / 30%
   cream / 10% dark across vertical scroll. Don't make every page feel
   like the same stack of components.

7. Some reference pages reference outdated info (e.g., "almost two decades
   of experience implementing AI strategies" on the AI page should be
   softened — generative AI is much newer than that). Flag obvious
   factual issues with a {/* TODO: verify - description */} comment
   rather than copying claims that don't hold up.
